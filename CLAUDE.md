# Кото-оборона

Мобильная браузерная игра в жанре merge + tower defense для Яндекс Игр. Коты-маги четырёх стихий защищают замок от мышиной армии. Игрок призывает котов, сливает одинаковых для роста уровня и смешивает разные стихии, открывая гибридов.

Полный дизайн — в `docs/GDD.md`. Играбельный HTML-прототип механик — в `docs/prototype.html` (только как справка по поведению, код оттуда не копировать как есть).

## Стек

- Phaser 3, TypeScript (strict), Vite
- Целевая платформа: Яндекс Игры (HTML5), приоритет — мобильный браузер, портретная ориентация
- Логическое разрешение 360×640, масштабирование `Phaser.Scale.FIT`

## Структура

```
src/
  main.ts            точка входа, конфиг Phaser
  adBreaks.ts        реклама для сцен: ролик с наградой и полноэкранная между уровнями (частоту держит `systems/Ads`)
  art.ts             готовый арт поверх рисунков кодом: загрузка атласов и фонов, `art.add(scene, id)`, `addArtOrShape` (картинка, а пока её нет — рисунок кодом)
  audio.ts           звуки и музыка поверх Phaser Sound: `audio.play(id)`, `audio.music(scene, id)`, отдельные выключатели звуков и музыки, паузы (скрытая вкладка, реклама)
  fonts.ts           загрузка веб-шрифтов до меню
  scenes/            Boot, Menu, Book, Bestiary (враги: открытые после первой победы, по нажатию — карточка `EnemyCard.ts`), Gear, Story (сценки перед уровнями), Intro (карточка «Новый враг» перед уровнем, где враг впервые выходит: `levels.json` → `intro`), Game, UI (HUD поверх Game)
  systems/           логика без отрисовки: Waves, Combat, Merge, Summon, Economy, Buildings (строения: постройка, улучшение, доход), Progress, Loadout, Gear, Chests, Campaign, Book, Bestiary, Story, Items (предметы: редкость, случайные бонусы из пула, разбор, прокачка, перенос старого снаряжения), Tutorial, Ads, Rewards, Simulation (бой без отрисовки), Bot (бот-игрок для подбора баланса: призывает, сливает, строит, продаёт)
  entities/          Cat, Building (строение в клетке поля), Enemy, Projectile, Hero; `*View.ts` — их картинки (у кота и строения общая основа `PieceView`)
  data/              JSON-конфиги: cats.json, enemies.json, levels.json, economy.json (цена и лимит призывов, продажа, строения), gear.json (метеор, ритуал, сундуки, `items` — редкости, пул бонусов, прокачка и легендарные предметы), ads.json, story.json, art.json (манифест арта: какие картинки ждёт игра, их размеры, группы и атласы; имена — в `systems/Art.ts`)
  platform/          площадка за интерфейсом `Platform`: `YandexPlatform` (SDK Яндекс Игр: реклама, данные игрока, язык, разметка боя) и `DevPlatform` (заглушка); выбор — при запуске, по наличию `/sdk.js`
  i18n/              строки RU/EN
public/assets/       шрифты (`fonts/`), сжатые звуки (`sfx/`) и музыка (`music/` со списком готовых треков `index.json`; собираются `npm run sfx`), готовый арт (`art/`: атласы, фоны уровней и список `index.json`, собираются `npm run art`)
assets-src/          сырые исходники ассетов (паки звуков Kenney в `sfx/`, треки в `music/`, картинки в `art/`); в git и в сборку не попадают
.githooks/           git-хуки (`pre-push` — типы и тесты перед отправкой)
scripts/             служебные скрипты (`sfx.mjs` — сжатие звуков, `art.mjs` — подготовка арта, `pack.mjs` — архив для Яндекс Игр)
balance/             отчёт о балансе главы: бот проходит уровни много раз (`npm run balance`)
smoke/               смоук-проверка в браузере (Playwright), см. `npm run smoke`
docs/                GDD и прототип; `ART_LIST.md` — список арта для художника (пишет `npm run art`), `CREDITS.md` — источники и лицензии звуков, музыки и шрифтов
```

## Правила

- Все числа баланса (урон, скорость, цены, волны) живут в `src/data/*.json`, не в коде.
- Логику держать отдельно от отрисовки: системы в `systems/` не зависят от Phaser там, где это возможно, чтобы их можно было тестировать.
- Весь вызов SDK Яндекс Игр — только через `src/platform/`. В режиме разработки там заглушки. SDK в игру не вшит: `/sdk.js` раздаёт сама площадка, игра подключает его при запуске (`loadYandexSdk`).
- Тексты для игрока — только через `i18n`, никаких строк в коде сцен. Новая строка — сразу в `ru.ts` и `en.ts`; `i18n.test.ts` следит, что перевод есть, а смоук в английской локали — что он помещается.
- Нажимаемые элементы — не меньше 44×44 в логических координатах (`MIN_TOUCH` в `layout.ts`), нажатие работает по всей видимой площади.
- Звук — только через `audio.play(id)` из `src/audio.ts`; громкость и ограничение частоты каждого звука — в `SOUND_FEEL` (`feel.ts`). Новый звук: строка в таблице `SOUNDS` в `scripts/sfx.mjs`, строка с исходником, паком, автором и лицензией в `docs/CREDITS.md` (без неё скрипт не соберёт ничего), `npm run sfx`, строка в `SOUND_FEEL`. Общий вес `public/assets/sfx` — до 500 КБ (скрипт проверяет).
- Музыка — только через `audio.music(scene, id)`: трек плавно сменяет прежний (`MusicMixer` в `systems/Sound.ts`), громкости и время перехода — в `MUSIC_FEEL` (`feel.ts`). Файл трека грузится при первом обращении и запуск игры не задерживает; пока трека нет в `public/assets/music/index.json`, игра молчит. Новый трек: строка в `MUSIC` в `scripts/sfx.mjs`, строка в `docs/CREDITS.md`, `npm run sfx`, строка в `MUSIC_FEEL`. Общий вес `public/assets/music` — до 1500 КБ. Звуки и музыка выключаются отдельно (меню и меню паузы), обе настройки — в сохранении.
- Реклама — только через `adBreaks` (`src/adBreaks.ts`): наградная по кнопке со значком ролика (`addAdButton`), полноэкранная — только при уходе с экрана итога боя. Числа — в `ads.json`.
- Продажа: пока игрок держит кота или строение, нижняя полоса — зона продажи (`GameEvent.SellOffer`); касание ведёт `GameScene`, HUD рисует зону, прячет кнопки и сам рисует взятое поверх экрана (`GameEvent.DragMove`/`DragEnd`): камера поля обрезана по его краю. Окно стройки и улучшения — `scenes/BuildPanel.ts`.
- Подсказки обучения (`systems/Tutorial.ts`, `scenes/TutorialOverlay.ts`) никогда не перехватывают касания; какие шаги на каком уровне и где стоит текст — в `levels.json` → `tutorial`.
- Пауза: бой останавливает `GameScene.pauseBattle()` (кнопка паузы, скрытая вкладка), всю игру на время рекламы — `Platform.onPause` (подключён в `BootScene`). Всё, что должно замирать на паузе, живёт в обновлении, анимациях и таймерах сцен Phaser, а не в `setTimeout`. Ускорение ×2 (кнопка в HUD, `GameScene.toggleSpeed`) — несколько обычных шагов боя за кадр и `timeScale` таймеров и анимаций сцены боя; держится до конца боя, пауза и реклама от него не зависят, пауза между рекламными роликами идёт в настоящих секундах.
- Переходы между сценами — через `fadeIn`/`fadeOut` из `scenes/transitions.ts`, отклик нажатия — через `addPressFeel` из `scenes/widgets.ts`; параметры всех анимаций и эффектов — в `feel.ts`.
- Арт: каждая картинка описана в `data/art.json`, имена — `artId` и `itemArtId` (`systems/Art.ts`). Отрисовка берёт картинку только через `art` (`src/art.ts`) и всегда оставляет рисунок кодом запасным вариантом: `addArtOrShape` для фигур, `art.addPlate` для фонов кнопок (растягиваются, подпись — текст), `art.addIcon` для значков. Готовое перечислено в `public/assets/art/index.json` и отмечено в `docs/ART_LIST.md` (оба пишет `npm run art`; тест следит, что список не отстал от манифеста); при запуске грузятся атласы и фон первого уровня, фон остальных — в `GameScene.preload`. Новая картинка: строка в манифесте, имя в `artId`, запасной рисунок в коде.
- Производительность отрисовки: `Graphics` заново разбивается на треугольники каждый кадр, поэтому всё неизменное (фон поля, панели, силуэты котов и мышей) запекается в текстуры (`bakeTexture`/`addBakedShape` в `scenes/textures.ts`), а круги и кольца эффектов — картинки из общих текстур. То, что в бою появляется и исчезает часто (снаряды, вспышки, монеты, всплывающие числа), берётся из `Pool` (`systems/Pool.ts`), а не создаётся заново.
- В режиме разработки (`npm run dev`) в углу поля — счётчик FPS и самого долгого кадра, внизу — кнопка «стресс»: 12 гибридов 5–6 уровня и 40 врагов (`src/debug.ts`). Ею проверяется производительность на телефоне. Кнопка «парад врагов» выпускает по одному врагу каждого типа, а `?enemies=all` в адресе подмешивает все типы в волны уровня — так смотрят врагов, которых в главе ещё нет.
- Размер сборки держать минимальным: никаких лишних библиотек без обсуждения.
- Логика в `systems/` покрывается тестами (Vitest, файлы `*.test.ts` рядом с системой). Новая или изменённая логика — вместе с тестами.
- После изменений в сценах и отрисовке (`src/scenes/`, `src/entities/*View.ts`, `src/layout.ts`, `src/feel.ts`) запустить `npm run smoke` и посмотреть скриншоты в `screenshots/` — до того, как просить меня проверить.
- Перед завершением задачи: `npm run build` без ошибок, `npm run typecheck` без ошибок и `npm test` проходит.
- Сохранение (`systems/Progress.ts`): новое поле — новая миграция в конец `MIGRATIONS` и тест на чтение старых версий. В разработке `?reset` в адресе стирает сохранение, `?lang=en` включает английский.
- Цвета в `data/*.json` — шесть шестнадцатеричных цифр, с `#` или без; в число их переводит только `parseColor` (`data/index.ts`), `colors.test.ts` сверяет результат с записанным.
- Особенности врагов (иммунитеты, сопротивления, лечение, подкоп, уклонение, полёт) — поля типа в `enemies.json`, логика — в `systems/Combat.ts`. У каждого врага с особенностью — свой признак в `drawEnemyBody` (`entities/EnemyView.ts`).
- Снаряжение — предметы инвентаря (`systems/Items.ts`): слот, редкость, бонусы из пула `gear.json` → `items.pool`, уровень. Бонусы боя собирает `itemsBonuses` из надетых предметов; новый вид бонуса — строка в пуле, поле в `GearBonuses` (`systems/Loadout.ts`), поддержка в системе боя и строка `item.bonus.<вид>` в i18n. Генерация предмета берёт всё случайное из переданного `rng` в одном порядке: одно зерно — один предмет. Первый бонус нового предмета — характерный для слота (`main` в правиле пула; у посоха — шанс стихии), по нему предмет назван: `itemName` (`systems/Items.ts`) отдаёт части названия, `scenes/itemTitle.ts` собирает строку из `item.name.<вид>`, слов слота и стихии и приставки редкости у эпических и легендарных; новый вид бонуса — ещё и строка `item.name.<вид>`. Экран — `scenes/GearScene.ts` (надетое, сетка инвентаря, карточка предмета).
- Сундуки (`systems/Chests.ts`): за сумму звёзд, за первое прохождение уровня на три звезды, малый — с шансом за победу, и за наградной ролик в меню с паузой по настоящему времени. Заработанные ждут в сохранении (`pending`) и открываются в меню по одному; числа — в `gear.json` → `chests` и `ads.json` → `chest`. В смоуке малый сундук сам не выпадает: его заказывает `__smoke.smallChest(true)`.
- Бот в отчёте о балансе и в страже играет без бонусов снаряжения (`noBonuses`): уровни должны проходиться со стартовыми предметами, а находки из сундуков делают игру легче, но не обязательны.
- Баланс уровней (`levels.json`) правится вместе с `npm run balance`: бот должен проходить каждый уровень, но не на три звезды с запасом, и сложность должна расти к концу главы. Страж в `systems/Bot.test.ts` падает, если это нарушено.
- Маленькие шаги: одна фича — один коммит. Сообщения коммитов на русском, в повелительном наклонении («Добавь ритуал смешения»).
- После каждого коммита — `git push`, но только после того, как прошёл `npm run check`. То же самое делает хук `.githooks/pre-push`: при ошибке типов или тестов отправка отменяется. Хук подключается один раз после клонирования: `git config core.hooksPath .githooks`.
- Работаем в ветке `main`. Отдельные ветки не создавать без просьбы.

## Команды

- `npm run dev` — локальный сервер (для телефона: `npm run dev -- --host`)
- `npm run build` — сборка в `dist/`
- `npm run typecheck` — проверка типов
- `npm test` — тесты систем (Vitest)
- `npm run check` — типы и тесты подряд; запускается перед каждым `git push` (хук `.githooks/pre-push`)
- `npm run balance` — отчёт о балансе: бот проходит каждый уровень 60 раз, таблица с долей побед, звёздами, потерями, временем, числом строений, продаж, призывов за волну и доходом строений; `RUNS=200 SEED=1000` — больше прогонов и другие бои, `TUNE=1` — подобрать `hpMult` уровней под целевые звёзды (перенести в `levels.json` вручную)
- `npm run sfx` — пересобрать `public/assets/sfx` из `assets-src/sfx` (нужны ffmpeg и распакованные паки Kenney, ссылки — в начале `scripts/sfx.mjs`)
- `npm run art` — пересобрать `public/assets/art` из `assets-src/art` по манифесту `src/data/art.json` (sharp): у исходника без прозрачности убирает однотонный фон, обрезает прозрачные края, приводит к размеру, собирает атласы webp, фоны уровней кладёт отдельными файлами; печатает вес стартовой загрузки (атласы и фон первого уровня) отдельно от фонов, которые грузятся при входе в уровень; общий вес — до 3 МБ. Каких исходников нет — тех картинок в игре нет
- `npm run smoke` — смоук-проверка: сборка, `vite preview`, headless Chromium 360×640, всё дважды — на русском и на английском, и третий раз — с заглушками арта (около 13 минут; одна локаль: `npm run smoke -- --project=ru`). Сценарии в `smoke/game.smoke.ts`: (1) игрок со старым сохранением версии 1: меню → звук и музыка → книга → бестиарий (пустой, затем с открытыми врагами и карточками) → инвентарь (старое снаряжение перенесено; карточка предмета, надеть, разобрать, карточка надетого; нажатия у углов ячеек) → сценка → бой: три кота, волна, монеты за рекламу, призыв сверх лимита волны, ускорение ×2, пауза с выключателями звука и музыки, сворачивание вкладки → поражение, «Второй шанс», «Ещё раз» → победа, удвоение, меню; (2) новый игрок: стартовые предметы, победа на три звезды с заказанным малым сундуком, три сундука по очереди (за три звезды, за сумму звёзд, малый), сундук за рекламу и отсчёт до следующего, разбор и улучшение надетого; (3) каждый из 10 уровней запускается, кот перетаскивается на нижнюю полосу (зону продажи) и продаётся, на четвёртом — стройка: окно, лавка, два улучшения, продажа строения; на последнем выходит король, сценка перед королём; (4) обучение: все подсказки (призыв, слияние, лимит призывов, продажа, гибрид, метеор, стройка на 4-м уровне), слияние и продажа перетаскиванием, метеор; (5) инвентарь с предметами всех редкостей: карточки эпических и легендарных предметов со сравнением, текст не заходит на кнопки; (6) парад врагов: все типы на дороге (`enemies-parade.png`), крот под землёй, всплывающие «Иммунитет» и «Мимо»; (7) цепочка уровней: победа → «Дальше» → снаряжение → бой пять раз подряд, затем победа → меню → уровень, с нажатиями до того, как экран проявился (этот сценарий идёт ещё и на сервере разработки, проект `dev`: там работают счётчик FPS и отладочные кнопки). Проект `art` повторяет сценарии `game.smoke.ts` на русском с заглушками всех картинок манифеста вместо пустого `assets/art` (снимки — в `screenshots/art/`) и с двумя поддельными треками музыки: так проверяются отрисовка готовым артом и смена треков между меню и боем. `smoke/yandex.smoke.ts` подсовывает игре поддельный `/sdk.js` и проверяет работу через `YandexPlatform`. На каждом экране проверяется, что нажимаемые элементы не меньше 44×44, а надписи помещаются в свои кнопки, не выходят за экран и не наезжают друг на друга. Снимки — в `screenshots/` (английские — в `screenshots/en/`). Случайность игры в проверке идёт от фиксированного зерна (`SMOKE_SEED` в `src/smoke.ts`, заново с каждого боя): призывы, состав волн и кристаллы в каждом прогоне одни и те же; вся случайность игры берётся из `random` (`systems/Random.ts`), не из `Math.random`. Падает при ошибке в консоли или если игра не дошла до экрана (тогда смотреть `test-results/`)
- `npm run pack` — сборка и архив `pack/kotooborona-<версия>.zip` для консоли Яндекс Игр (проверяет index.html в корне, имена файлов и размер)
- `npm run perf` — замер худшего случая в headless: первый уровень, «стресс», 30 с; печатает FPS и работу игры за кадр без замедления и с процессором ×4

## Текущий этап
