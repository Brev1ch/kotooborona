# Кото-оборона

Мобильная браузерная игра в жанре merge + tower defense для Яндекс Игр. Коты-маги четырёх стихий защищают замок от мышиной армии. Игрок призывает котов, сливает одинаковых для роста уровня и смешивает разные стихии, открывая гибридов.

Полный дизайн — в `docs/GDD.md`. Играбельный HTML-прототип механик — в `docs/prototype.html` (только как справка по поведению, код оттуда не копировать как есть).

## Стек

- Phaser 3, TypeScript (strict), Vite
- Целевая платформа: Яндекс Игры (HTML5), приоритет — мобильный браузер, портретная ориентация
- Логическое разрешение 360×640, масштабирование `Phaser.Scale.FIT`

## Структура

```
src/
  main.ts            точка входа, конфиг Phaser
  adBreaks.ts        реклама для сцен: ролик с наградой и полноэкранная между уровнями (частоту держит `systems/Ads`)
  audio.ts           звуки поверх Phaser Sound: `audio.play(id)`, выключатель, паузы (скрытая вкладка, реклама)
  fonts.ts           загрузка веб-шрифтов до меню
  scenes/            Boot, Preload, Menu, Book, Gear, Game, UI (HUD поверх Game)
  systems/           логика без отрисовки: Waves, Combat, Merge, Summon, Economy, Progress, Loadout, Gear, Chests, Campaign, Book, Ads, Rewards, Simulation (бой без отрисовки), Bot (бот-игрок для подбора баланса)
  entities/          Cat, Enemy, Projectile, Hero
  data/              JSON-конфиги: cats.json, enemies.json, levels.json, gear.json, ads.json
  platform/          площадка за интерфейсом `Platform`: `YandexPlatform` (SDK Яндекс Игр: реклама, данные игрока, язык, разметка боя) и `DevPlatform` (заглушка); выбор — при запуске, по наличию `/sdk.js`
  i18n/              строки RU/EN
public/assets/       спрайты, шрифты (`fonts/`), сжатые звуки (`sfx/`, собираются `npm run sfx`)
assets-src/          сырые исходники ассетов (паки звуков Kenney); в git и в сборку не попадают
scripts/             служебные скрипты (`sfx.mjs` — сжатие звуков, `pack.mjs` — архив для Яндекс Игр)
balance/             отчёт о балансе главы: бот проходит уровни много раз (`npm run balance`)
smoke/               смоук-проверка в браузере (Playwright), см. `npm run smoke`
docs/                GDD и прототип
```

## Правила

- Все числа баланса (урон, скорость, цены, волны) живут в `src/data/*.json`, не в коде.
- Логику держать отдельно от отрисовки: системы в `systems/` не зависят от Phaser там, где это возможно, чтобы их можно было тестировать.
- Весь вызов SDK Яндекс Игр — только через `src/platform/`. В режиме разработки там заглушки. SDK в игру не вшит: `/sdk.js` раздаёт сама площадка, игра подключает его при запуске (`loadYandexSdk`).
- Тексты для игрока — только через `i18n`, никаких строк в коде сцен.
- Нажимаемые элементы — не меньше 44×44 в логических координатах (`MIN_TOUCH` в `layout.ts`), нажатие работает по всей видимой площади.
- Звук — только через `audio.play(id)` из `src/audio.ts`; громкость и ограничение частоты каждого звука — в `SOUND_FEEL` (`feel.ts`). Новый звук: строка в таблице `SOUNDS` в `scripts/sfx.mjs`, `npm run sfx`, строка в `SOUND_FEEL`. Общий вес `public/assets/sfx` — до 500 КБ (скрипт проверяет).
- Реклама — только через `adBreaks` (`src/adBreaks.ts`): наградная по кнопке со значком ролика (`addAdButton`), полноэкранная — только при уходе с экрана итога боя. Числа — в `ads.json`.
- Пауза: бой останавливает `GameScene.pauseBattle()` (кнопка паузы, скрытая вкладка), всю игру на время рекламы — `Platform.onPause` (подключён в `BootScene`). Всё, что должно замирать на паузе, живёт в обновлении, анимациях и таймерах сцен Phaser, а не в `setTimeout`.
- Переходы между сценами — через `fadeIn`/`fadeOut` из `scenes/transitions.ts`, отклик нажатия — через `addPressFeel` из `scenes/widgets.ts`; параметры всех анимаций и эффектов — в `feel.ts`.
- Производительность отрисовки: `Graphics` заново разбивается на треугольники каждый кадр, поэтому всё неизменное (фон поля, панели, силуэты котов и мышей) запекается в текстуры (`bakeTexture`/`addBakedShape` в `scenes/textures.ts`), а круги и кольца эффектов — картинки из общих текстур. То, что в бою появляется и исчезает часто (снаряды, вспышки, монеты, всплывающие числа), берётся из `Pool` (`systems/Pool.ts`), а не создаётся заново.
- В режиме разработки (`npm run dev`) в углу поля — счётчик FPS и самого долгого кадра, внизу — кнопка «стресс»: 12 гибридов 5–6 уровня и 40 врагов (`src/debug.ts`). Ею проверяется производительность на телефоне.
- Размер сборки держать минимальным: никаких лишних библиотек без обсуждения.
- Логика в `systems/` покрывается тестами (Vitest, файлы `*.test.ts` рядом с системой). Новая или изменённая логика — вместе с тестами.
- После изменений в сценах и отрисовке (`src/scenes/`, `src/entities/*View.ts`, `src/layout.ts`, `src/feel.ts`) запустить `npm run smoke` и посмотреть скриншоты в `screenshots/` — до того, как просить меня проверить.
- Перед завершением задачи: `npm run build` без ошибок, `npm run typecheck` без ошибок и `npm test` проходит.
- Сохранение (`systems/Progress.ts`): новое поле — новая миграция в конец `MIGRATIONS` и тест на чтение старых версий. В разработке `?reset` в адресе стирает сохранение, `?lang=en` включает английский.
- Баланс уровней (`levels.json`) правится вместе с `npm run balance`: бот должен проходить каждый уровень, но не на три звезды с запасом, и сложность должна расти к концу главы. Страж в `systems/Bot.test.ts` падает, если это нарушено.
- Маленькие шаги: одна фича — один коммит. Сообщения коммитов на русском, в повелительном наклонении («Добавь ритуал смешения»).
- Работаем в ветке `main`. Отдельные ветки не создавать без просьбы.

## Команды

- `npm run dev` — локальный сервер (для телефона: `npm run dev -- --host`)
- `npm run build` — сборка в `dist/`
- `npm run typecheck` — проверка типов
- `npm test` — тесты систем (Vitest)
- `npm run balance` — отчёт о балансе: бот проходит каждый уровень 60 раз, таблица с долей побед, звёздами, потерями и временем; `RUNS=200 SEED=1000` — больше прогонов и другие бои, `TUNE=1` — подобрать `hpMult` уровней под целевые звёзды (перенести в `levels.json` вручную)
- `npm run sfx` — пересобрать `public/assets/sfx` из `assets-src/sfx` (нужны ffmpeg и распакованные паки Kenney, ссылки — в начале `scripts/sfx.mjs`)
- `npm run smoke` — смоук-проверка: сборка, `vite preview`, headless Chromium 360×640; меню → кнопка звука (выключить и включить) → книга котов и назад → первый уровень → снаряжение (выбор предмета в каждом слоте нажатиями у углов плашек) → «В бой» → 3 кота → первая волна → монеты за рекламу → пауза кнопкой и «Продолжить» → сворачивание вкладки (игра должна встать на паузу) и «Продолжить» → поражение, «Второй шанс», «Ещё раз» → победа, удвоение награды, «В меню»; скриншоты шагов в `screenshots/`. Второй тест (`smoke/yandex.smoke.ts`) подсовывает игре поддельный `/sdk.js` и проверяет работу через `YandexPlatform`. На каждом экране проверяет, что нажимаемые элементы не меньше 44×44. Падает при ошибке в консоли или если игра не дошла до экрана (тогда смотреть `screenshots/failure.png`)
- `npm run pack` — сборка и архив `pack/kotooborona-<версия>.zip` для консоли Яндекс Игр (проверяет index.html в корне, имена файлов и размер)
- `npm run perf` — замер худшего случая в headless: первый уровень, «стресс», 30 с; печатает FPS и работу игры за кадр без замедления и с процессором ×4
